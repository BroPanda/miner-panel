# Miner Panel — майнінг на відеокарті NVIDIA

## Встановлення

Завантаж файл зі сторінки **Releases** (праворуч на GitHub). Python і щось інше ставити не треба.

**Windows 10/11** — `MinerPanel.exe`
1. Поклади файл у **окрему порожню теку** (наприклад `D:\MinerPanel\`): поруч із ним панель зберігатиме налаштування й гаманці.
2. Запусти. Windows може показати «Windows захистила ваш ПК» (файл без платного підпису) — натисни **Докладніше → Однаково запустити**.
3. Дозволь права адміністратора: без них не змінити потужність відеокарти.
4. Майстер першого запуску допоможе вибрати монету, пул і вписати гаманець.
5. Windows Defender часто вважає майнери загрозою і видаляє їх. Якщо так сталося — у панелі є кнопка, що додає майнер у винятки.

**Linux (x86_64)** — `MinerPanel-linux-x86_64.tar.gz`
1. Потрібен драйвер NVIDIA (`nvidia-smi` має працювати).
2. Розпакуй в окрему теку: `tar -xzf MinerPanel-linux-x86_64.tar.gz`
3. Перший раз: `./MinerPanel-linux-x86_64 --install` (попросить пароль — щоб дозволити керування потужністю карти і додати ярлик у меню).
4. Далі — з меню програм або `./MinerPanel-linux-x86_64`.

Панель лише **знижує** частоти й потужність карти (напругу не чіпає) і повертає заводські налаштування після зупинки. Майнери завантажуються з їхніх офіційних GitHub і перевіряються за SHA256. Комісія розробника майнера видна при виборі майнера.

## Нова панель 2.0 (Windows і Linux)

Нова версія — звичайне вікно на Python + Qt, той самий набір можливостей і ті самі файли даних (`settings.json`, `coins.json`, `wallets.json`, `stats.json`, `bin\`). Python ставити не треба — програма зібрана в один файл.

| | Windows | Linux |
|---|---|---|
| Файл | `MinerPanel.exe` у теці з даними | `MinerPanel` у теці з даними |
| Перший запуск | двічі клацнути (попросить права адміністратора) | `chmod +x MinerPanel` і `./MinerPanel --install` (пароль — щоб дозволити розгін) |
| Далі | двічі клацнути | з меню програм або `./MinerPanel` |

- Розділи: **Огляд** (гроші і стан разом, повідомлення з кнопкою дії), **Пристрої** (цей ПК і риги HiveOS однаково, графіки, режим роботи), **Гроші** (баланс, прогноз, бухгалтерія, світло), **Монети** (рейтинг, що майнити, гаманці), **Налаштування**, **Журнал**.
- Перемикач **Простий / Експертний** угорі: у простому — головне і зрозумілі слова, в експертному — частоти, шари, логи, коди КТ. Біля термінів — «?» з поясненням.
- Закриття вікна згортає панель біля годинника, майнінг триває; там же сповіщення про проблеми (пул, риг офлайн, перегрів, виплата).
- `MinerPanel --test` — справжні дані, але відеокарту не чіпає і файли не змінює; `--demo` — макет на зразкових даних.
- Дві панелі одночасно не працюють: нова не запуститься, поки відкрита стара `MinerPanel.ps1`.
- Збірка: `build-windows.bat` → `dist\MinerPanel.exe`; на Linux `sh build-linux.sh` → `dist/MinerPanel`; або обидві на GitHub (`.github/workflows/build.yml`). Тести: `.venv\Scripts\python -m pytest`.

Ліцензія — [MIT](LICENSE).

## Стара панель (PowerShell, лише Windows) — архів у `old-panel\`

Стара панель більше не використовується і лежить в `old-panel\` (MinerPanel.ps1, lib, miners, pools, mine.bat). Щоб тимчасово повернутись до неї: закрити нову панель, скопіювати вміст `old-panel\` у корінь проєкту і запустити **`mine.bat`** — дані (settings.json, stats.json тощо) в обох версіях спільні. Нижче — опис її можливостей; більшість діє і в новій панелі.

Запуск: **`mine.bat`**. Відкриється панель, яка попросить права адміністратора: без них не змінити ліміт потужності карти.

**Стоп** або закриття панелі зупиняє майнер і повертає карту до заводських налаштувань: ліміт потужності, частоти ядра і пам'яті. Навіть якщо панель упаде, налаштування скине прихований процес-сторож.

## Структура

| Шлях | Що там |
|---|---|
| `MinerPanel.ps1` | вікно панелі |
| `coins.json` | монети: алгоритм для кожного майнера, пул, гаманець, оцінка хешрейту |
| `miners\*.ps1` | адаптери майнерів: SRBMiner-MULTI, lolMiner, Rigel, BzMiner, OneZeroMiner |
| `pools\*.ps1` | адаптери пулів: Kryptex, HeroMiners, generic (будь-який пул, без статистики) |
| `lib\` | відеокарта, оновлення майнерів, ринкові дані, hashrate.no (еталони карт, ключ `HashrateNoKey` у settings.json), автопідбір, бухгалтерія (`Ledger.ps1`), ферма HiveOS (`HiveOs.ps1`) |
| `bin\<майнер>\<версія>\` | встановлені версії майнерів, активна записана в `current.txt` |
| `settings.json` | тарифи, запобіжники, профілі розгону **для кожної монети** |
| `stats.json` | бухгалтерія воркерів (контрольні точки, видачі) і енергія та світло цього ПК |
| `logs\miner.log` | лог поточного майнера |

## Монети

У правій колонці:
- вибираєш монету і майнер;
- вписуєш гаманець і воркер і натискаєш **Зберегти** (зберігається в `coins.json`).

Якщо змінити монету під час майнінгу, панель сама перезапустить майнер.

Щоб додати монету, скопіюй блок у `coins.json` і заповни поля:
- `miners` — назва алгоритму для кожного майнера, що його підтримує;
- `miner` — майнер за замовчуванням;
- `pool.type` — `kryptex`, `herominers` або `generic`;
- `pool.urls` — адреси `host:port`, перша основна;
- `pool.fee` — комісія пулу частками, наприклад `0.01` = 1%;
- `wtm` — назва монети на WhatToMine, щоб працював рейтинг;
- `estimate` — хешрейт у H/s і ватти для рейтингу, поки монета не виміряна.

**Гаманці** зберігаються в `wallets.json` окремо для кожної монети (за тікером):
- для однієї монети можна мати кілька адрес, наприклад власний гаманець і адресу біржі;
- вибрана в списку адреса діє для цієї монети на всіх пулах;
- **✎** редагує назву чи адресу вибраного гаманця, **+** додає новий (назва + адреса), **−** видаляє вибраний.

**Ціна** монети береться з вибраного джерела (список «Ціна» в блоці «Монета»):
- **CoinGecko** (середня по біржах) — за замовчуванням;
- **конкретна біржа** зі списку CoinGecko (наприклад Ourbit чи BigONE для Pearl);
- **WhatToMine**.

Посилання «CoinGecko ↗» поруч із ціною відкриває сторінку монети.

**Тариф:** якщо лічильник однозонний, зніми галочку «2 зони». Тоді весь час діє один тариф і денні налаштування розгону, а автопідбір робить один прохід.

Під час першого запуску адреси з `coins.json` переносяться сюди автоматично.

**До виплати** показує орієнтовний час до мінімальної виплати пулу:
- рахується за хешрейтом **усіх** online-воркерів твоєї адреси на пулі;
- для воркера цього ПК береться живий хешрейт;
- приклад: `4,0 % з 1 PRL · ≈ 21 год 51 хв (20.10 ~13:29) · 1 воркер, 60 TH/s`.

Це оцінка за WhatToMine: фактична швидкість залежить від удачі пулу і схеми виплат.

**Підтверджено / в обробці** показує обидві частини балансу і їхню суму: `0,7571 + 0,2374 = 0,9945 PRL`. «В обробці» — це винагорода за вже знайдені блоки. Вона дозріває сама, навіть якщо більше не майнити.

**Виплачено** — усього виплачено пулом по цій монеті (і в ₴), плюс сума й дата останньої виплати.

**Можна відключитись?** підказує, чи можна зупинити майнінг або перейти на іншу монету чи пул, не лишивши монет на цьому пулі. Панель сама нічого не перемикає, це лише підказка, а повне пояснення є у спливній підказці при наведенні:
- **«ні — до виплати бракує N»** (жовтим): підтверджене + в обробці ще менше за поріг виплати. Якщо відключишся, ця сума лишиться на пулі, поки знову не майниш тут;
- **«✓ так»** (зеленим): на виплату вже вистачає. «В обробці» — винагорода за вже знайдені блоки, вона дозріє сама, тож виплата прийде без подальшого майнінгу.

**Рейтинг монет** рахує прибуток за добу з урахуванням денного і нічного тарифу. Дані беруться з WhatToMine (мережа, нагорода, курс) і CoinGecko (курс BTC у ₴), ключ API не потрібен. Вкладка має два окремі блоки:
- **Мій поточний**: монета, яку ти зараз майниш, з твоїм розгоном. Показано ₴ на добу, хешрейт і споживання, живі («зараз») або виміряні раніше, а поруч відхилення від еталону цієї монети у %, окремо для прибутку і для споживання. Для споживання показано і різницю у ватах, і у %, наприклад «+15 Вт (+21%)». Мінус означає, що економніше за еталон.
- **Рейтинг за еталоном**: усі монети, включно з поточною, з однаковими умовами: хешрейт і споживання RTX 3060 з hashrate.no, а якщо їх немає, оцінка з `coins.json` (колонка «Джерело»). **Сортування і рекомендація «Найвигідніша за еталоном» рахуються лише за еталоном.**

На «Головній» підказка показує найвигіднішу монету за еталоном, а поруч, якщо ти вже майниш найвигіднішу, твій фактичний результат.

## Бухгалтерія

Вкладка «Бухгалтерія» показує, скільки **монет** намайнив кожен воркер і скільки належить кожному власнику, якщо на спільний гаманець майнять різні ПК чи люди. Дані зберігаються в `stats.json` (`ledger`, `payouts`), власники воркерів — у `settings.json` (`WorkerOwners`).

**Як ділиться.** Монети, які пул реально нарахував на гаманець (виплати + підтверджений баланс), діляться між воркерами **пропорційно до їхньої роботи після контрольної точки (КТ)**:
- робота — накопичувальний лічильник пулу. На HeroMiners це сума складності прийнятих шар (`hashes`), саме за неї пул нараховує монети. Kryptex дає лише кількість шар, тому там розподіл приблизний («≈»);
- результат залежить лише від КТ і поточної відповіді пулу, а не від того, коли панель його опитувала. Тому **на всіх ПК з однаковою КТ числа однакові**, і поки панель вимкнена, нічого не губиться;
- «В обробці» (блоки, що ще дозрівають) у розподіл не входить, доки пул їх не підтвердить;
- рядок «разом» звіряє розподілене з нарахованим пулом (✓).

**Контрольна точка і обмін без сервера.**
- **Закрити період** фіксує поточний розподіл як нову КТ (зручно робити, коли видаєш монети людям) і показує код.
- **Код КТ** — короткий текст `MPK1:…` з КТ, власниками і видачами. Надішли його іншим учасникам у месенджер.
- **Імпорт КТ** застосовує чужий код, якщо його КТ новіша за твою. Після цього числа збігаються.
- Якщо пул скинув лічильник воркера, з'являється ⚠: інші ПК могли цього не бачити, тож закрий період і передай код.

**Власники і видачі.**
- Подвійний клік по воркеру (або «Власник…») призначає власника. Воркер цього ПК за замовчуванням належить «Я».
- **Видати…** записує, скільки монет ти переказав власнику. Таблиця власників показує: намайнено − видано = залишок до видачі.

**Рахунки.** Ведуться окремо для кожної пари «пул + монета + гаманець». Поточна монета опитується разом із блоком «Пул», а інші, за якими вже є записи, по черзі раз на 10 хв. Колонка «Пул (6 год)» — хешрейт воркера за пулом, «Джерело» — за майнером цього ПК. Якщо після 6 год роботи вони розходяться більш ніж на 25 %, обидві клітинки підсвічуються: можливі відхилені шари або чужий воркер під твоїм ім'ям.

Новий адаптер пулу має повертати `earned` (виплачено + підтверджений баланс) і `workers[].work` (накопичувальна робота воркера), інакше розподілу не буде.

Перший запуск переносить старий журнал «Статистики» у контрольну точку без втрат, а копію попереднього файлу зберігає в `stats.json.bak`.

**Цей ПК.** Розрахункові монети (за живим хешрейтом), фактичні монети (частка цього воркера за пулом), енергія, світло і чистий прибуток. Світло кожен оплачує сам, тому для чужих воркерів панель його не рахує.

**Що рахується як енергія:** лише відеокарта (nvidia-smi) і лише поки працює майнер, тож процесор і решта ПК не враховуються. Розділити споживання карти по процесах драйвер не дозволяє. Тому з нього віднімається **простій карти**: панель вимірює його сама через 30 с після зупинки майнера, а високі значення (гра, відео) відкидає. Поки простій не виміряно, рахується вся карта. кВт·год записуються у форматі «на видобуток / уся карта».

Кнопка «Скинути все» очищує бухгалтерію й облік цього ПК (з підтвердженням). Після цього наступне оновлення пулу знову розділить усе нараховане за накопиченою роботою воркерів, а щоб знову зійтися з іншими учасниками, імпортуй їхній код КТ.

## Ферма HiveOS

Вкладка «Ферма» показує риги HiveOS і керує ними через офіційний API (`api2.hiveos.farm`). Працює звідусіль, не лише в домашній мережі.

**Підключення.** У HiveOS: Account → API tokens → створи персональний токен. Встав його в поле «Токен HiveOS» і натисни «Зберегти». Токен лежить лише в `settings.json` (`HiveOsToken`) і дає повний доступ до акаунта, тож нікому не передавай цей файл.

**Що видно.** Усі ферми й воркери (оновлення раз на хвилину): статус (онлайн / майнер зупинено / без хешрейту / офлайн), хешрейт, монета й майнер, польотний лист, споживання, максимальна температура, шари. По вибраному воркеру видно кожну карту: °C, вентилятор, Вт, частоти, хешрейт.

**Керування вибраним воркером.**
- «Старт», «Стоп» (з підтвердженням), «Перезапуск» майнера.
- «Польотний лист» → «Застосувати»: перемкнути монету чи пул (з підтвердженням, майнер на ризі перезапуститься).
- «Профіль розгону» → «Застосувати»: готовий профіль розгону HiveOS. Свій розгін для ферми панель не створює, обмеження задаються в HiveOS.

**Нагляд.** Якщо риг офлайн, його майнер зупинено або понад 5 хв немає хешрейту, вкладка стає «Ферма ⚠», а причина з'являється в рядку стану. Галочка «Автоперезапуск…» (за замовчуванням вимкнена, бо в HiveOS є власний watchdog) перезапускає майнер, якщо він працює, але 10 хв без хешрейту, і не частіше ніж раз на 30 хв. Зупинений вручну майнер панель не запускає.

**Бухгалтерія.** Воркер HiveOS зіставляється з воркером пулу за назвою: польотний лист зазвичай передає `%WORKER_NAME%`. Якщо на пулі назва інша, задай відповідність у `settings.json → HiveWorkerMap`, наприклад `{ "rig1": "farm-rig1" }`. Монета береться з польотного листа (тікер + пул з `coins.json`), її рахунок починає відстежуватися, а в колонці «Джерело» видно хешрейт за HiveOS для звірки з пулом. Світло ферми (за споживанням з HiveOS і твоїм тарифом) рахується лише поки панель відкрита.

Команди, надіслані на риги, записуються в `logs\panel.log`. У тестовому режимі (`-Test`) команди не надсилаються ніколи. Тестові перемикачі: `PANEL_TEST_HIVE_FAKE=1` (зразок даних без мережі) і `PANEL_TEST_HIVE=1` (реальні запити лише для читання з токеном).

## Майнери та оновлення

Раз на добу панель перевіряє нові версії на офіційних GitHub. Якщо є оновлення, рядок майнера стає жовтим.
- **Встановити / оновити** завантажує реліз, перевіряє його за SHA256, який публікує GitHub, і розпаковує в окрему папку.
- **Відкат версії** повертає попередню версію: попередні версії не видаляються.

Папку `C:\Code\mining` треба додати у виключення Windows Defender, бо він видаляє майнери.

## Режими і розгін

| Режим | Мета | Автопідбір |
|---|---|---|
| **Ефективний** | найбільше хешрейту на 1 Вт | один прохід, результат іде в день і ніч |
| **Прибутковий** | найбільше ₴ за годину з урахуванням тарифу | два проходи: день і ніч |
| **Свій (вручну)** | твої власні значення | немає, лише вручну |

Кожен режим має для кожної монети два набори налаштувань: **День** і **Ніч**. На вкладці «Розгін» видно обидва рядки (ліміт, ядро, пам'ять, зсув пам'яті), а рядок, що діє зараз, позначено «▶ … — діє». Зміни в ньому застосовуються одразу, зміни в іншому рядку лише зберігаються.

Галочка **«Окремі налаштування на ніч»** вмикає перехід: у нічну зону тарифу рядок «Ніч» вмикається сам. Якщо зняти галочку (або «2 зони» на вкладці «Тарифи»), цілодобово діє рядок «День», а прибутковий автопідбір робить один прохід за середнім тарифом доби. Значення нічного рядка не стираються.

**Зсув пам'яті, МГц** (вкладка «Розгін») — розгін або зниження частоти відеопам'яті через NVAPI драйвера NVIDIA:
- **межі залежать від моделі карти** («захист від дурня»): для RTX 3060 −500…+1000 МГц, для невідомих моделей обережні −500…+500;
- **діє лише під час майнінгу:** Стоп, закриття панелі, аварія майнера чи сторож скидають зсув до 0;
- поточний зсув видно в рядку «Ядро / пам'ять»;
- корисний для алгоритмів, що залежать від пам'яті. Для Pearl (залежить від ядра) розгін пам'яті майже нічого не дає.

**Пам'ять «до N МГц (економно)»** обмежує частоту пам'яті і знижує споживання там, де алгоритм залежить від ядра, як Pearl. Якщо драйвер цього не підтримує, у рядку «Режим» з'явиться «пам'ять: не підтримується».

**Автопідбір:**
1. Стартує з рекомендованої точки монети (в ефективному режимі) або з денного профілю (у прибутковому).
2. Іде вгору або вниз кроками по 100 МГц, поки оцінка росте, і уточнює ±50 МГц.
3. Одна точка займає 1,5 хв. У прибутковому режимі з увімкненою ніччю робить два проходи (день і ніч), вже виміряні точки бере з кешу.

**Запобіжники:**
- Поля розгону дозволяють лише значення, які драйвер підтримує саме для цієї карти: ядро від мінімальної до максимальної підтримуваної частоти (для RTX 3060: 405–2130 МГц, 0 = без обмеження), ліміт потужності від мінімального до максимального (100–170 Вт), пам'ять — тільки частоти зі списку драйвера, «Макс. °C» — не вище цільової температури карти (83 °C). Межі видно на вкладці «Розгін».
- Розгін лише обмежує частоти і потужність від заводських значень: напругу панель не чіпає.
- **Макс. Вт** — стеля ліміту потужності.
- **Шукати ядро до** — стеля частоти для автопідбору.
- **Макс. °C**: на межі ядро знижується на 100 МГц, а на 8 °C вище межі майнінг зупиняється.

## Що перевірено, а що ні

- **SRBMiner і BzMiner:** перевірені наживо на Pearl. BzMiner майнить лише на NVIDIA, процесор і вбудована графіка вимкнені.
- **Rigel:** запуск і API перевірені на Ergo з тестовим логіном.
- **lolMiner:** перевірено лише формат API (у режимі бенчмарку).
- **OneZeroMiner** (Pearl, лише NVIDIA, комісія розробника 1%): саме на ньому знято еталон hashrate.no для RTX 3060. Розгін майнеру не передається, його робить панель. Телеметрія вимкнена (`--disable-telemetry`). Компактне ядро (≈99% хешрейту при на 10–20% меншому споживанні) вмикається, лише якщо пам'ять зафіксована на 810 МГц до старту майнера, тому в профілях Pearl тримай «Пам'ять: до 810 МГц». Формат API в документації не описаний, тож читання хешрейту треба перевірити наживо.
- **Kryptex:** баланс і воркери перевірені на твоїй адресі.
- **HeroMiners:** воркери і хешрейт перевірені на тестовому воркері. Поля балансу ще не перевірені, бо до першого нарахування вони порожні.
- **Обмеження частоти пам'яті:** не перевірене, для цього потрібні права адміністратора.
